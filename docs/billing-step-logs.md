# 计费块日志与耗时观测

一条新日志对应一个计费 step。HTTP/SSE 一次请求一个 step；WebSocket 每个 response.create 一个 step。会话只通过 reservation_request_id 关联，不再累计成一条日志。

WebSocket 终止事件的用量、价格、模型和日志在同一计费事务里保存。日志 ID 由会话 ID 与响应 ID 确定，终止事件重放不会重复收费。响应缺少 ID 时沿用终止事件内容哈希去重；无法可靠区分内容完全相同且不带 ID 的独立响应。

同一连接提前发送的多个 response.create 按接收顺序关联终止事件；这是运行时串行执行响应的协议边界，不支持供应商交错返回多个活跃响应的归属推断。连接结束时，已完成 step 不重写，尚未完成的 step 各自保留中断记录。失败终止事件保留失败记录；有 usage 时依 usage 计费，没有 usage 的明确失败按零费用处理。成功但 usage 不完整继续使用现有保守结算策略，日志的定价状态保持未完成。

## 观测目的与边界

所有间隔使用同一进程的 time.Time 单调时钟计算，JSON 保留微秒精度（以毫秒表示）。没有完整起止点就不生成该阶段，不以零表示未观测。

| 观测 | 起止 | 用来判断 |
| --- | --- | --- |
| HTTP 准入步骤 | handler 开始，依次到鉴权、并发准入、读请求体、模型与限额检查、订阅预留完成 | 请求慢在读入、排队还是准入处理 |
| HTTP 运行时执行 | 调用 Serve 前到 Serve 返回后立即采时 | 协议处理、上游执行和下游写入的整体耗时 |
| HTTP 首响应数据 | handler 开始到第一次非空 ResponseWriter.Write 进入前 | 服务端多久开始写响应正文，不是首 token 或客户端到达时间 |
| 上游尝试 | executor 进入到返回；流式执行到通道结束；原生 HTTP 路径单独标注“至响应头” | 重试次数、每次执行耗时与错误 |
| 获取连接 | GetConn 到 GotConn | 连接获取总耗时，包含池等待或建连；不再重复相加 DNS/TCP/TLS |
| 请求发送、首包等待 | GotConn 到成功 WroteRequest，再到 GotFirstResponseByte | 发送与响应首字节等待；不声称知道供应商内部排队时间 |
| WebSocket 准备 | 收到完整 response.create 到准备转发 | 首轮准入、连接与请求准备；不包含等待用户下一轮输入 |
| WebSocket 响应 | 准备转发到 Relay 收到终止事件 | 每轮等待与接收响应；不含终止事件后数据库事务及该事件的客户端写入 |
| WebSocket 首响应事件 | 本轮请求收到到本轮第一个响应事件收到 | 事件响应延迟，不等于模型开始输出文字 |
| HTTP 计费调度与处理 | 响应边界到 finalizer 开始，再到计费处理完成 | 后台结算是否拥塞；单列、不增加响应耗时，不含日志插入 |
| WebSocket 用量与价格处理 | 终止事件收到到价格计算结束 | 终止后处理耗时，不含后续计费事务与日志插入 |

上游尝试是运行时执行的子区间，连接与首包又是尝试的子区间。它们只供诊断，不能相加为请求总耗时。取消逐次 Read/Write 的计时包装，删除旧三方归因桶、重叠推算，以及把累计 Read/Write 阻塞拼成连续时间轴的做法。一个 executor 内发生多次连接获取时，省略无法一一配对的网络子区间，保留执行总耗时。流式 chunk 的到达时间不再冒充 HTTP 首字节。

## 历史与统计

迁移 11 将历史 WebSocket 会话日志标记为 legacy_session，不修改历史费用、用量或虚构轮次时钟。历史日志仍可查，页面标注“历史会话”。新统计逐条计数，列表不隐藏独立 step；延迟分位数排除历史会话日志。旧版已归档的日汇总无法恢复 step 数，仍保留原始汇总口径。

详细请求内容仍使用原有采样和 32 KiB 截断规则，并脱敏凭据头。结构化用量与遥测独立于原始正文采样。

## 验证

覆盖 step 不继承会话累计值、稳定 ID、终止重放、子毫秒精度、空写入不触发首字节、未完成尝试不捏造终点、运输层重放不拼接网络计时；日志页有浏览器测试。数据库事务和汇总测试需要 TEST_DATABASE_URL 指向专用 PostgreSQL 测试库。

## 列表中的首 Token 与缓存率

列表直接显示 first_token_ms 和缓存率（cached_tokens / prompt_tokens）。first_token_ms 是本计费块开始到 Relay 观测到首个非空生成增量的时间，支持正文、推理、拒绝文字及工具调用参数；跳过 created、角色、心跳和 usage 等元数据事件。HTTP 按 SSE 完整事件解析，支持事件跨 Write 分块；WebSocket 每个 step 重置观测。此数值表示生成内容在 Relay 的可见时间，不表示供应商内部生成时间。

原有 ttft_ms 保留首响应口径，两者不混用。历史日志、非流式响应、没有可识别生成增量的响应，首 Token 显示“—”；没有输入 Token 时缓存率显示“—”。
