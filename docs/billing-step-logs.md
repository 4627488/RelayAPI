# 请求计量、用量记录与结算

计量口径以 [yetone/magpie](https://github.com/yetone/magpie) 的
`ffc1d64e5e50d8681763268b5e2df080c8954a19` 版本为依据，采用独立输入与缓存桶、
缓存 TTL、完整请求结果和按有效流式样本计算的性能指标。

HTTP/SSE 每次生成一条记录，WebSocket 每轮生成一条记录。记录独立于是否扣费：
成功、失败、取消、拒绝、免费、零用量和未定价请求均保留。预热、连接和 token
计数不是生成用量，不进入生成统计。鉴权失败没有可信租户归属，仅进入运行日志。

只有可靠完整用量和确定价格才能结算实际费用。缺用量或价格时不估算、不扣费，
释放预留，记录未知状态；更新价格不会追溯补扣。预留用于准入并发控制，不是费用。
HTTP 的扣费与记录原子提交；WebSocket 的每轮计量、扣费和记录同样原子提交，
零费用终态也持久化并去重。客户端在终态前断开，保留取消记录而不捏造用量。

## Token 与价格

| 字段 | 口径 |
| --- | --- |
| `input` | 普通输入，不包含缓存读取或缓存写入 |
| `output` | 全部输出，包含推理 |
| `cache_read` | 缓存读取，与普通输入分开 |
| `cache_write` | 全部缓存写入 |
| `cache_write_1h` | 缓存写入中 1 小时 TTL 的子集，其余为 5 分钟 |
| `reasoning` | 输出中的推理子集，仅作明细，不额外计费 |
| `total_tokens` / 汇总 `tokens` | `input + output`，不包含缓存流量 |
| `cache_unknown` | 单次为布尔值；汇总为缓存未知请求的完整 prompt token 数 |

完整 prompt 为 `input + cache_read + cache_write`。汇总缓存命中率为
`(cache_read - cache_unknown_read) / (input + cache_read + cache_write - cache_unknown)`；分母无有效样本时返回
`null`，页面显示“—”。未知缓存不视为未命中。质量不完整的用量不会变成确认费用。

价格保持 nano-USD 单位，普通输入、缓存读取、5 分钟写入、1 小时写入和输出分别计价。
`tiers` 按完整 prompt 超过 `above` 的最高层对整次调用定价；刚好等于阈值不进入下一层。
models.dev 的 context tiers 和 `cache_write_1h` 会被同步。Claude 未给 1 小时写入价格时，
按 Magpie 的规则使用输入价的 2 倍；其他模型缺少此价时使用普通缓存写入价。
`reasoning_nano_usd_per_token` 是兼容旧价格数据的字段，不再产生额外推理费用。
图片模型继续使用精确模态用量，避免文本和图片重复计费。

## 观测目的与边界

所有间隔使用同一进程的 time.Time 单调时钟计算，JSON 保留微秒精度（以毫秒表示）。没有完整起止点就不生成该阶段，不以零表示未观测。

| 观测 | 起止 | 用来判断 |
| --- | --- | --- |
| HTTP 准入步骤 | handler 开始，依次到鉴权、并发准入、读请求体、模型与限额检查、订阅预留完成 | 请求慢在读入、排队还是准入处理 |
| HTTP 运行时执行 | 调用 Serve 前到 Serve 返回后立即采时 | 协议处理、上游执行和下游写入的整体耗时 |
| HTTP 首响应数据 | handler 开始到第一次非空 ResponseWriter.Write 进入前 | 服务端多久开始写响应正文，不是首 token 或客户端到达时间 |
| 上游尝试 | executor 进入到返回；流式执行到通道结束；原生 HTTP 路径单独标注“至响应头” | 重试次数、每次执行耗时与错误 |
| 获取连接 | GetConn 到 GotConn | 连接获取总耗时，包含池等待或建连；不再重复相加 DNS/TCP/TLS |
| 请求发送、首包等待 | GotConn 到成功 WroteRequest，再到 GotFirstResponseByte | 发送与响应首字节等待；不声称知道供应商内部排队时间 |
| WebSocket 准备 | 收到完整 response.create 到准备转发 | 首轮准入、连接与请求准备；不包含等待用户下一轮输入 |
| WebSocket 响应 | 准备转发到 Relay 收到终止事件 | 每轮等待与接收响应；不含终止事件后数据库事务及该事件的客户端写入 |
| WebSocket 首响应事件 | 本轮请求收到到本轮第一个响应事件收到 | 事件响应延迟，不等于模型开始输出文字 |
| HTTP 计费调度与计算 | 响应边界到 finalizer 开始，再到用量与价格计算结束 | 后台调度与计算是否拥塞；不增加响应耗时，不含后续计费事务 |
| WebSocket 用量与价格处理 | 终止事件收到到价格计算结束 | 终止后处理耗时，不含后续计费事务与日志插入 |

上游尝试是运行时执行的子区间，连接与首包又是尝试的子区间。它们只供诊断，不能相加为请求总耗时。取消逐次 Read/Write 的计时包装，删除旧三方归因桶、重叠推算，以及把累计 Read/Write 阻塞拼成连续时间轴的做法。一个 executor 内发生多次连接获取时，省略无法一一配对的网络子区间，保留执行总耗时。流式 chunk 的到达时间不再冒充 HTTP 首字节。

## 历史与统计

迁移 16 将旧的包含缓存读取的输入转换为独立普通输入，并把原首响应时间迁入
`first_byte_ms`。历史费用、余额和流水不重新计算；原输入、总 Token 与首响应值另存 `legacy_usage` 供审计。旧记录已保存的缓存计数继续作为观测证据；迁移 17 修正了曾把这些计数统一标为未知的问题。
旧归档没有 Key 身份，明确归入“历史归档（未记录 Key）”。
旧日归档无法恢复请求发生的分钟，保留原 UTC 日期，不能凭空恢复本地日边界。

新归档按 UTC 分钟、租户、模型和 Key 聚合，保留全部可加指标，包括取消、拒绝、
未定价、缓存 TTL、首 Token 样本及解码样本。移动明细与归档在同一事务；报表通过
单条 UNION 查询读取两者，避免归档并发造成重复或丢失。总计、按天、模型、Key 和用户
使用同一份聚合数据。日界按 `timezone` 指定的 IANA 时区计算，包含夏令时。

详细请求内容仍按原有采样与 32 KiB 截断规则保存并脱敏凭据头，结构化计量和性能数据
不依赖正文采样。租户接口继续隐藏内部凭据、提供商和诊断链路。

上线切换时应先停止旧版本实例写入，再启动新版本执行迁移；v1/v2 的输入字段语义不同，不能混跑。

## 总览观测口径

总览与用量接口的 `summary`、`daily`、`models`、`api_keys` 和 `users` 使用相同指标。
`mean_ttft_ms` 按 `timed` 样本计算均值；`tokens_per_second` 为
`decode_out × 1000 / decode_ms`，并返回有效样本数 `decode_n`，不平均单次速度。
HTTP 取消状态在响应结束边界采集，后台结算不读取 handler 返回后自动取消的 context。
这些加性性能指标随归档保留。延迟、首 Token 与首响应分位数仅使用保留的 step，
不从归档推算。全局提供商观测仅面向管理员，且明确只覆盖保留明细。

## 首 Token 与生成速度

`ttft_ms` 与 `first_token_ms` 都表示首次生成内容；`first_byte_ms` 单独表示首次响应数据。
支持 Responses、Chat、Anthropic Messages 与 Gemini 的文字、推理、拒绝文字和工具参数。
跳过 created、角色、心跳和纯 usage；SSE 支持跨 Write 分块。`first_text_ms` 和
`first_reasoning_ms` 分别保存文字与可见推理的首次到达时间。

生成速度按 Magpie DecodeOf 的样本规则计算：推理回复优先只计首段文字后的正文输出，
没有可靠文字、推理或时间窗口时不显示速度；排除小于 100 ms、超过 10,000 token/s、
流量集中在窗口小部分、长等待后的短突发以及正文远快于前序可见推理的样本。
流量分布记录 10%–90% 内容到达跨度。时间点和内容采样有界，原始正文不作为永久计量数据。
客户端看到的速度和首 Token 都是 Relay 的观测，不声称是供应商内部生成时间。

## 接口

- `GET /api/usage`、`GET /api/admin/usage`、`GET /api/rai/manage/usage`：
  `days=1..365`，或 `period=today|7d|30d|all`；`timezone=Asia/Singapore` 等 IANA 时区。
  管理员可加 `user_id`，其近 24 小时输出吞吐量也遵循此用户筛选。
- `GET /api/logs` 与管理员版本：原有分页、Key、模型、时间等筛选继续可用；
  `status` 新增 `canceled`、`rejected`、`retried`、`unpriced`。
- 价格接口新增 `cache_write_1h_nano_usd_per_token` 与 `tiers`；每层包含
  `above` 和输入、输出、缓存读取及两类缓存写入单价，沿用 nano-USD/token 单位。
- 响应带 `metering_version=2`；Token 明细使用上表中的 Magpie 字段名，前端同步切换。

## 验证

数据库测试覆盖免费、失败、取消、拒绝、未定价请求持久化，余额扣费与记录回滚、
并发结算不重复收费、零费用 WebSocket 终态去重、迁移重入不重复转换，
以及跨时区归档前后的用量、费用、缓存率、解码速度和 Key 归因一致性。
流式测试覆盖跨帧解析、独立缓存桶、1 小时写入和首次文字/推理观测。
数据库测试要求 `TEST_DATABASE_URL` 指向专用 PostgreSQL 测试库。

## 列表悬浮详情

悬停或点击列表中的耗时、Tokens、费用，可打开默认 shadcn Popover；键盘使用 Tab 定位、Enter 打开、Escape 关闭，手机端点击数值即可。浮层分为耗时、用量、计费和链路，直接使用当前日志数据，不为每一行额外请求原始正文。

耗时展示 v5 的阶段偏移、持续时间、事件标记，以及已记录的尝试序号、提供商、模型、凭据标识、连接复用、远端地址和错误。详情页复用同一份观测表。嵌套阶段不能相加为总耗时，响应结束后的计费处理单列；无 v5 数据时明确提示，不推算缺失阶段。

用量保留精确 Token 数、两种 TTL 的缓存写入、缓存读取与命中率、推理、图片及请求/响应体积；计费展示费用、定价与结算状态、价格来源和已记录单价；链路展示模型映射、上游身份、订阅、关联 ID 和错误。未采集字段显示“未记录”，零值保留。
