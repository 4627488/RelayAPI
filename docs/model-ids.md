# 对外模型 ID 与兼容

公开模型元数据优先采用 `作者/模型名`，例如 `openai/gpt-5.4`、`x-ai/grok-4.5`、`moonshotai/kimi-k2.5`。作者命名空间不代表实际调用渠道：通过 Codex、兼容接口或其他渠道提供的 Grok 仍使用 `x-ai/`。这是一套 Relay 的规范化投影，不承诺与 OpenRouter 的模型清单、版本别名或变体命名完全相同。

## 命名来源

可明确识别的 GPT/Codex/o 系列、Grok、Claude、Gemini、Kimi、DeepSeek 使用已知作者命名空间。其他模型仅在 models.dev 有模型名精确匹配的已知第一方作者资料时补前缀；例如 Alibaba 的模型使用 `qwen/`、Mistral 使用 `mistralai/`。不使用承载渠道或聚合商名称猜测作者，不通过去除日期、改变模型名大小写或改写变体后缀来拼出另一模型。

已带命名空间的 ID 保留原文。来源不明确的自定义模型保留原 ID。显式 Key 别名优先；自动生成的 ID 不能覆盖运行时已有完整 ID，也不能覆盖用户别名。旧 ID 被用户别名遮蔽时，不为它自动生成另一个名字，以免改变已有别名含义。

## 目录行为

普通 `/v1/models` 列表及其他模型元数据入口优先输出无冲突的规范 ID。生成的规范条目带有 `canonical_slug` 和 `legacy_ids`，继承原模型的能力、描述与显示名。旧 ID 的单模型元数据查询仍有效，返回请求的旧 ID，并附上规范 ID；新 ID 也可直接查询。

Codex 目录将规范 ID 作为可选项，同时保留完整的隐藏旧条目，以抑制内置目录合并造成的重复。无工具等原本不可见的模型不会因规范化变为可见。目录仍按当前 Key 的实际模型授权过滤；规范化不是授权。

网页模型列表使用独立的 `/api/models`。该接口保留原 `id` 供 Key 权限编辑等既有消费者使用，新增 `canonical_id` 作为无冲突的可调用展示名。网页优先显示、搜索和复制 `canonical_id`，同时仍支持按原 ID 搜索；旧服务器未提供该字段时回退到 `id`。底层授权与结算选项不因展示名改变。

rai session 的 `models` 同时保留新旧可调用 ID，避免已保存旧模型名的 rai 配置失效；默认模型在无冲突时投影为规范 ID。Key 的自定义别名保持原名。既有全局配置、Codex 会话和持久化模型选择不强制迁移。

## 日志、报表与其他展示

日志列表和详情新增只读的 `canonical_model`、`canonical_requested_model`，优先用于展示。原始 `model`、`requested_model`、`actual_model`、`upstream_model`、计价模型和请求/响应正文保留；详情同时展示有变化的原始请求/路由名。显式请求别名和与路由不同的旧请求名不会被猜成另一个作者。已有完整 ID 冲突、通配模式和未知名称保持原文。

日志按完整规范 ID 搜索时兼容旧原名；精确模型筛选匹配规范 ID 与可验证的原名，保持租户、状态和时间过滤。该兼容仅用于读取日志，不引入推理通路的通用去前缀回退。

用量归因、错误统计、价格目录、订阅的可用模型列表和热力图（含导出的 SVG）通过额外展示字段使用同一服务端命名规则。历史模型即使不再发布，已知作者的旧 ID 仍可规范展示。统计按原模型归集，金额与数量不重算、不合并；权限/路由编辑表单继续提交原 ID，上游观测点和原始计价依据保留其诊断名称。

rai session 的 `model_ids` 提供原名到规范名的明确映射。新版 `rai models` 文本输出去除重复旧名；`--json` 保留旧的 `models/default_model`，额外输出 `canonical_models/canonical_default_model`，避免破坏原有脚本。旧服务器缺少映射时保留原显示。

## 请求、权限和计费

旧 ID 继续调用原模型。新 ID 在 HTTP、Responses WebSocket 首轮及后续轮次解析为原 ID，再执行既有模型权限、订阅准入、价格解析和上游模型路由。配置目标为新 ID 的 Key 别名也先解析到原模型。请求日志沿用既有别名记录方式，可关联客户端请求名与实际模型。

不改写数据库中的模型、历史价格、订阅授权或上游模型名称；这些配置继续以运行时原模型 ID 为准。例如原模型为 `gpt-5.4` 时，`openai/gpt-5.4` 的请求仍检查 `gpt-5.4` 的权限与价格。显式发布的完整 ID 则仍使用它原有的权限与路由，不会被同尾名的旧 ID 抢占。

未知的完整 ID 不会通过通用的“去前缀”规则放行。只有为已发布原模型生成的无冲突映射可用。目录 revision 同时包含规范映射、权限、别名和能力快照；推理响应与目录使用同一 ETag 规则。

## 验证

测试覆盖作者识别、精确 models.dev 资料、未知名称保留、命名冲突、自定义别名优先、新旧详情查询、跨协议目录过滤、隐藏旧 Codex 条目及 WS 每轮改写。真实 Codex 0.163.0 的目录测试通过生产目录入口读取规范 ID，验证对应上下文和 priority 请求。真实商业上游仍沿用原有适配与验收边界。
