# Agent Note: Pin Docker web builds to pnpm 10

Status: implemented

## Problem

`Build RelayAPI image` failed on `pnpm install --frozen-lockfile` with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` for lockfile entries published the same day (`rolldown@1.2.6`, `eslint-plugin-react-refresh@0.5.5`, `systeminformation@5.33.4`). The frontend CI job on the same commit passed.

The image used `corepack enable` with no version pin. On `node:24-alpine` that activates pnpm 11, whose default `minimumReleaseAge` is 1440 minutes and then rejects a lockfile that already contains newer packages. CI and `.cursor/install.sh` already pin `pnpm@10`.

## Decision

Activate `pnpm@10` in the root and `web/` Dockerfiles the same way install.sh does. Do not set `minimumReleaseAge: 0`; the lockfile is valid under the project's existing pnpm major.

## Alternatives considered

**Set `minimumReleaseAge: 0` in `pnpm-workspace.yaml`.** Unblocks pnpm 11 but drops the cooling-off check for every future install, including local ones that later upgrade.

**Downgrade the too-new lockfile entries.** Undoes the same-day security upgrade and will recur on the next vite/rolldown bump.

**Wait 24 hours.** Works once; the next unpinned Node 24 image build fails again after any same-day lockfile bump.

## Consequences

Image builds use the same pnpm major as CI. A later move to pnpm 11 should be an explicit repo-wide pin, not a silent corepack default.
